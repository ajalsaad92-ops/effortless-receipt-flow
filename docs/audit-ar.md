# تقرير فحص مشروع `effortless-receipt-flow`

**المستودع:** https://github.com/ajalsaad92-ops/effortless-receipt-flow
**تاريخ الفحص:** ٣١ تموز/يوليو ٢٠٢٦
**ما هو المشروع فعلياً:** تطبيق ويب (PWA) لتشخيص سيارات جنرال موتورز عبر OBD2 — يتصل بجهاز ELM327 عن طريق Web Bluetooth أو Web Serial، يقرأ أكواد الأعطال والحساسات الحية، ويشرحها بمساعد ذكي بالعربية والإنجليزية.
**التقنيات:** TanStack Start + React 19 + Vite 7 + Tailwind 4، منشور على Cloudflare Workers.

---

## ما تم التحقق منه فعلياً (وليس مجرد قراءة)

| الفحص | النتيجة |
|---|---|
| `npm install` | ✅ نجح (٦٢٣ حزمة) |
| `npx tsc --noEmit` | ✅ **نظيف تماماً — صفر أخطاء أنواع** |

| إعادة إنتاج أخطاء ELM327 | ✅ **مثبتة تجريبياً بكود تشغيلي** (التفاصيل في §٢ و§٣) |

# القسم الأول: الأخطاء

## 🔴 خطأ ١ — نقطة `/api/chat` مفتوحة للعالم بلا أي حماية

**الملف:** `src/routes/api/chat.ts:16-40`

```ts
POST: async ({ request }) => {
  const body = await request.json();
  const key = process.env.LOVABLE_API_KEY;   // ← مفتاح مدفوع
  const result = streamText({ model: gateway("google/gemini-3.6-flash"), ... });
```

لا مصادقة، لا حدّ لعدد الطلبات (rate limit)، لا تحقق من مصدر الطلب (Origin)، ولا حدّ لطول الرسائل. أي شخص يكتشف الرابط يستطيع تشغيل سكربت يستنزف رصيد `LOVABLE_API_KEY` بالكامل — والفاتورة على صاحب المشروع.

**المفارقة:** الحماية جاهزة في المستودع ولا أحد يستخدمها. `requireSupabaseAuth` في `src/integrations/supabase/auth-middleware.ts` مكتوب بالكامل (١٠٩ أسطر) — وعدد من يستورده: **صفر**.

> **تصحيح بعد التنفيذ:** ربط `requireSupabaseAuth` بهذه النقطة كان اقتراحاً خاطئاً مني.
> التطبيق **لا يحتوي تسجيل دخول أصلاً** — كل البيانات محلية — فلو رُبط لأعاد 401 لكل
> مستخدم حقيقي. الحماية المطبَّقة فعلياً: تحقق من Origin + حدّ معدل لكل IP + سقف
> لعدد الرسائل وحجم الطلب. أما `auth-middleware.ts` فقد حُذف مع باقي بقايا Supabase.

**مشكلة ثانية في نفس الملف:** `body.vehicleContext` نص يتحكم به المستخدم ويُلصق مباشرة داخل الـ system prompt (سطر ٢٩-٣٢). أي أحد يستطيع إرسال `vehicleContext` يحتوي تعليمات تتجاوز شخصية المساعد (prompt injection).

**الإصلاح المقترح:**
```ts
// ١. حدّ معدل بسيط لكل IP عبر Cloudflare (أو KV) قبل أي شيء
// ٢. تحقق من الـ Origin
if (new URL(request.headers.get("origin") ?? "").host !== new URL(request.url).host) {
  return new Response("Forbidden", { status: 403 });
}
// ٣. حدّ حجم المدخلات
if (body.messages.length > 40) return new Response("Too many messages", { status: 413 });
// ٤. افصل بيانات السيارة عن التعليمات — ضعها كرسالة user لا داخل system
```

## 🔴 خطأ ٢ — مؤقّت قديم يمسح ردّاً جارياً (مُثبت تجريبياً)

**الملف:** `src/lib/obd.ts:184-203`

```ts
const answer = new Promise<string>((resolve, reject) => {
  this.resolvers.push(resolve);
  setTimeout(() => {              // ← لا يُلغى أبداً
    this.resolvers = this.resolvers.filter((r) => r !== resolver);
    this.buffer = "";             // ← يمسح مخزن أمر آخر تماماً
    reject(new Error("timeout"));
  }, timeoutMs);
});
```

المؤقّت لا يُلغى عند نجاح الأمر. إذا ردّ الجهاز خلال ٢٠ ملّي ثانية، يبقى مؤقّت الـ ٥ ثوانٍ مسلّحاً وينفجر لاحقاً — و`this.buffer = ""` يمسح ردّاً **لأمر لاحق** يكون في منتصف التجميع.

صفحة `live.tsx` تقرأ ٦ حساسات كل ثانية بمهلة ٥ ثوانٍ لكل واحد ⇒ حوالي **٣٠ مؤقّتاً معلّقاً في كل لحظة**، كل واحد قنبلة تمسح المخزن.

الضرر الأكبر يقع على الردود متعددة الإطارات (ISO-TP) التي تصل على دفعات: `readVin()` و`readMode09Text()` و`03` عند وجود عدة أعطال ومسح الـ PIDs المدعومة.

**الإثبات** — شغّلت الكود الفعلي مع محاكي ELM327:

```
الأمر 0902 (قراءة رقم الهيكل VIN)
المتوقع:  "49 02 01 31 47 31 4A 31 32 33 34 35 36 37"
المستلم:  "4A 31 32 33 34 35 36 37"        ← النصف الأول مُحيَ
```

النتيجة العملية: **رقم هيكل خاطئ أو ناقص**، وبالتالي `decodeVin()` يعطي سنة صنع وموديل ومحرّكاً خاطئين، وهذه المعلومات المغلوطة تُرسل بعد ذلك للمساعد الذكي كـ"حقائق عن السيارة".

## 🔴 خطأ ٣ — ردّ متأخر يُرضي الأمر التالي (مُثبت تجريبياً)

**الملف:** `src/lib/obd.ts:42-50` مع `184-203`

عند انتهاء المهلة تُفرَّغ قائمة `resolvers`، لكن ردّ الجهاز المتأخر **لا يزال قادماً**. وعندما يصل، تنفّذ `pushChunk` السطر:

```ts
const resolve = this.resolvers.shift();   // ← يلتقط resolver الأمر التالي
resolve?.(chunk);
```

فيتسلّم الأمر التالي بيانات الأمر السابق. عطل مهلة واحد يُفسد كل ما بعده.

**الإثبات:**
```
010C (دوران المحرك) — انتهت مهلته
0105 (حرارة الماء) — المتوقع: "41 05 5A"
                     المستلم: "41 0C 1A F8"   ← بيانات دوران المحرك!
```

`readPid()` تنجو جزئياً لأنها تتحقق من رقم الـ PID في الرد، لكن **لا حماية إطلاقاً** في `parseDtcResponse()` و`readMode09Text()` و`readAdapterInfo()` والكونسول الخام في `controls.tsx`. النتيجة: أكواد أعطال وهمية أو ناقصة تظهر للمستخدم.

**الإصلاح لـ ٢ و٣ معاً** (تعديل صغير في `sendNow`):

```ts
private seq = 0;

private async sendNow(command: string, timeoutMs: number): Promise<string> {
  if (!this.writer && !this.serialWriter) throw new Error("not-connected");
  const ticket = ++this.seq;          // بطاقة لكل طلب
  this.buffer = "";
  this.resolvers = [];
  let timer: ReturnType<typeof setTimeout> | undefined;

  const answer = new Promise<string>((resolve, reject) => {
    // لا يقبل الردّ إلا صاحب البطاقة الحالية
    this.resolvers.push((v) => { if (ticket === this.seq) resolve(v); });
    timer = setTimeout(() => {
      if (ticket !== this.seq) return;   // لم يعد أمرنا — لا تلمس شيئاً
      this.resolvers = [];
      this.buffer = "";
      reject(new Error("timeout"));
    }, timeoutMs);
  });

  const payload = new TextEncoder().encode(`${command}\r`);
  if (this.serialWriter) await this.serialWriter.write(payload);
  else if (this.writer.writeValueWithoutResponse) await this.writer.writeValueWithoutResponse(payload);
  else await this.writer.writeValue(payload);

  try { return await answer; }
  finally { clearTimeout(timer); }     // ← المفتاح: إلغاء المؤقّت دائماً
}
```

## 🟠 خطأ ٤ — قيم حساسات مُلفّقة تُعرض كقراءات حقيقية

**الملف:** `src/routes/live.tsx:54`

```ts
const current: LiveReading = { rpm: 0, speed: 0, coolant: 0, load: 0, intake: 0, throttle: 0, voltage: 14 };
```

`voltage` تبدأ بـ **١٤ فولت مكتوبة يدوياً**. وأمر `ATRV` يُستدعى مرة كل ١٠ دورات فقط، ولا يكتب فوق القيمة إلا عند نجاح القراءة — والتعليق في الكود نفسه يعترف: *"not all clones answer ATRV"*.

فإذا لم يجب الجهاز على `ATRV` أبداً (شائع جداً في الأجهزة المقلّدة)، تبقى القيمة ١٤، وتنتقل إلى `analyzeTrend()`، وتصل إلى `diagnostics.ts:179` التي تُخرِج:

> **"نظام الشحن سليم"** — من رقم لم يُقرأ من السيارة إطلاقاً.

هذه أخطر صيغة للخطأ في تطبيق تشخيصي: أن يطمئن المستخدم بناءً على رقم مخترع. قد يكون الدينامو تالفاً فعلاً والتطبيق يقول "سليم".

**نفس فئة الخطأ في باقي الحقول:** كلها تبدأ من صفر، ولا يوجد تمييز بين "لم يُقرأ بعد" و"قُرئ وقيمته صفر". وهذه الأصفار المصطنعة تُصدَّر أيضاً في ملف CSV (`live.tsx:113`) كأنها قياسات حقيقية.

**الإصلاح:** اجعل النوع `Partial<LiveReading>` أو استخدم `null`، واعرض `—` بدل الرقم، واجعل قواعد `diagnostics.ts` تتخطى أي حقل `null` بدل أن تحكم عليه.

## 🟠 خطأ ٥ — مكتبة Supabase كاملة تُحمَّل في المتصفح بلا أي فائدة

**الملفات:** `src/start.ts:22` ← `src/integrations/supabase/auth-attacher.ts`

`attachSupabaseAuth` مسجّل كـ `functionMiddleware` عام، وهو يستورد عميل Supabase. النتيجة في البناء الفعلي:

```
.output/public/assets/index-6SORFHEv.js    ٦٥٨ كيلوبايت (١٩٤ مضغوطة)
```

**الإصلاح:** احذف `functionMiddleware: [attachSupabaseAuth]` من `src/start.ts`. إن لم تكن تنوي استخدام Supabase، احذف مجلد `src/integrations/` كاملاً وأزل `@supabase/supabase-js` و`@lovable.dev/cloud-auth-js` من `package.json`.

## 🟡 خطأ ٦ — التطبيق يدّعي أنه PWA لكنه ليس كذلك

يوجد `public/manifest.webmanifest` كامل (`display: standalone`، أيقونات، `theme_color`) و`<link rel="manifest">` في `__root.tsx:62` — لكن **لا يوجد Service Worker إطلاقاً** (لا ملف، ولا `navigator.serviceWorker.register` في أي مكان).

النتيجة:
- لا يعمل بدون إنترنت — وهذا تطبيق ورشة، والتغطية في الكراجات والمواقف المغلقة ضعيفة أو معدومة.
- متصفح Chrome على أندرويد لا يعرض زر "التثبيت" أصلاً لأنه يشترط SW يعالج أحداث `fetch`.
- المكوّن `InstallHint.tsx` مكتوب لعرض تلميح التثبيت — ولا يُستدعى في أي صفحة.

**الإصلاح:** أضف `vite-plugin-pwa` مع تخزين مؤقت لقاعدة الأكواد (`dtc-data.ts` و`pids.ts` ثابتة تماماً وتصلح للعمل دون اتصال).

**الإصلاح:** في `connectBle()` أضف:
```ts
device.addEventListener("gattserverdisconnected", () => this.handleDrop());
```
ومرّر رد نداء من `ObdProvider` يستدعي `setStatus("idle")`.

### ٢. أزل التبعيات غير المستخدمة

مُتحقَّق منها بالبحث في كامل `src/`:

```
jspdf  jspdf-autotable  ogl  lenis  date-fns  zod  @hookform/resolvers
```
صفر استخدام في أي مكان. و`jspdf` + `jspdf-autotable` وحدهما ثقيلتان جداً.

وهذه تُستخدم **فقط** داخل `components/ui/` الميت، فتذهب معه:
```
recharts  cmdk  vaul  embla-carousel-react  react-hook-form
react-day-picker  input-otp  react-resizable-panels  framer-motion
```

> **قياس فعلي بعد التنفيذ** (لا تقدير): الملف الرئيسي نزل من **٦٥٨ ← ٤٦١ كيلوبايت**
> (مضغوطاً: **١٩٤ ← ١٤٣**)، وإجمالي جافاسكربت في العميل من **١٠٣٨ ← ٨٥٣ كيلوبايت**.
> توقّعي السابق بـ"ما دون ٢٠٠" كان مبالغاً فيه: الباقي هو React 19 + TanStack Router
> نفسه، وتقليصه يحتاج عملاً آخر (تقسيم الحزم) خارج نطاق هذا التنظيف.

### ٤. أضف سكربتات مفقودة واختبارات

`package.json` لا يحتوي `typecheck` ولا `test`، ولا يوجد أي اختبار في المشروع:


ودوال التحليل النقي هي أوضح ما يستحق الاختبار — بلا متصفح ولا جهاز:

- **`.lovable/plan.md`** — خطة تصميم مفصّلة لصفحة `admin.reports.tsx` **غير موجودة في المشروع**
- **تعليق في `router.tsx:11-12`** يشرح سلوك التخزين المؤقت بمثال: *"an approver seeing a freshly submitted expense"*

هذا ليس تجميلاً: مطوّر جديد (أو أنت بعد ستة أشهر) سيفتح `supabase/migrations` ويظن أن للتطبيق قاعدة بيانات ونظام صلاحيات. والأسوأ أن قاعدة Supabase الحقيقية قد تكون لا تزال حيّة بجداول ذلك المشروع.

**الإصلاح:** وحّد الاسم على `gm-obd`، اكتب `README.md`، واحذف `supabase/` و`.lovable/plan.md` كلياً (أو انقلها لفرع أرشيفي إن كان مشروع المصاريف لا يزال مطلوباً).

### ٦. وحّد مدير الحزم

المستودع فيه **`package-lock.json` و`bun.lock` معاً** إضافة إلى `bunfig.toml`. الملفان سيتباعدان حتماً، وستحصل على نسخ تبعيات مختلفة بين جهازك والنشر. اختر واحداً واحذف الآخر.

### ٧. `.env` مرفوع في Git

الملف مرفوع و`.gitignore` **لا يغطي `.env`**.

المفتاح الموجود فيه من نوع `sb_publishable_` — أي مفتاح عام مصمَّم للظهور في المتصفح (وهو فعلاً موجود في حزمة العميل المبنية)، فليس تسريباً. **لكن** الخطر أن هذا الملف صار مساراً معتاداً للرفع؛ أول مرة يُضاف فيها `SUPABASE_SERVICE_ROLE_KEY` أو `LOVABLE_API_KEY` سيُرفع معه تلقائياً — وهذان مفتاحان حقيقيان: الأول يتجاوز كل قواعد RLS، والثاني يمثل رصيداً مدفوعاً.

**الإصلاح:** أضف `.env` إلى `.gitignore` الآن، وارفع `.env.example` بالأسماء فقط بلا قيم.

### ٨. عالج الأخطاء بدل ابتلاعها بصمت

يوجد **٤١ كتلة `catch` فارغة** في `src/lib/obd.ts` وحدها. بعضها مقصود ومبرَّر (وضع OBD غير مدعوم على هذه السيارة)، لكن النمط يخفي أعطالاً حقيقية: عندما يفشل فحص كامل، لا يبقى أي أثر يساعد على المعرفة.

**الإصلاح:** أضف سجلاً دائرياً بسيطاً داخل `ObdConnection` (آخر ١٠٠ أمر ورد وخطأ)، واعرضه كـ "سجل التشخيص" في صفحة `controls.tsx`. سيجعل دعم المستخدمين ممكناً بدل التخمين — وسيوفّر على الفور دليلاً على الخطأين ٢ و٣ عند أي مستخدم.

### ٩. حسّن تجربة `live.tsx`

الحلقة تقرأ الحساسات الستة تسلسلياً، ومع أجهزة BLE البطيئة قد تتجاوز الدورة الواحدة ثانيتين، فتبدو المؤشرات جامدة.

- اقرأ `rpm` و`speed` كل دورة، والباقي كل ٣ دورات (لا يتغير بسرعة أصلاً)
- اعرض عمر آخر قراءة لكل مؤشر ("منذ ٤ ثوانٍ") ليعرف المستخدم أن الرقم قديم
- استخدم `readSupportedPids()` أولاً لتتخطى الحساسات غير المدعومة بدل انتظار مهلة كل واحد

### ١٠. حسّن إمكانية الوصول

- أشرطة التقدّم في `live.tsx` و`sensors.tsx` عبارة عن `<div>` بعرض متغيّر بلا `role="progressbar"` ولا `aria-valuenow` — قارئ الشاشة لا يرى القيمة
- الأزرار الأيقونية فقط تفتقر لـ `aria-label` (زر الإرسال في `assistant.tsx` وحده يملكها)
- ألوان الحالة (`text-success` / `text-destructive`) هي الفارق الوحيد أحياناً — أضف أيقونة أو نصاً لمن لا يميّز الألوان

### ١١. تحذير السلامة على الفحوصات ثنائية الاتجاه

`controls.tsx` ينفّذ أوامر `bidirectional` (فحص مشغّلات) بضغطة زر واحدة على شارة "ثنائي الاتجاه". أوامر تشغيل مروحة أو مضخة وقود على سيارة تعمل تستحق مربع تأكيد صريحاً مثل ما فعلته بالفعل — وأحسنت — مع مسح الأعطال في `scan.tsx`.

## ⏸️ ما أُجِّل عمداً — ولماذا

هذه اقتراحات حقيقية، لكن كل واحد منها **ميزة قائمة بذاتها لها سطح أخطاء خاص**،
ولا يمكن التحقق منها هنا بلا جهاز ELM327 وسيارة حقيقية. تنفيذها على عمياء أسوأ
من تركها:

| البند | سبب التأجيل |
|---|---|
| **Service Worker / PWA** | نشر SW معطوب في تطبيق PWA أسوأ من عدم نشره؛ يحتاج اختبار تثبيت حقيقي على أندرويد وسيناريو تحديث النسخة |
| **اللغة في كوكي** (إزالة وميض RTL) | يمسّ SSR والجذر؛ يحتاج اختبار تصفح فعلي بالحالتين |
| **إعادة تصميم دورة `live.tsx`** (أولويات PID، عمر القراءة) | ضبط الإيقاع بلا جهاز حقيقي تخمين؛ الإصلاحات الحالية تكفي للصحة |
| **`npm audit fix`** | يرفع `vite` إصداراً ثانوياً؛ يجب أن يُشغَّل ويُختبر البناء على جهازك (الثغرات في أدوات التطوير لا الإنتاج) |
| **سجل التشخيص الدائري** | مفيد، لكنه ميزة واجهة جديدة لا إصلاح خطأ |
| **`crypto.randomUUID()` للمعرّفات، معالجة امتلاء `localStorage`** | تغييرات بيانات تحتاج ترحيلاً للمستخدمين الحاليين |
| **توسيع نافذة سنة VIN، تشديد كشف الوحدات (`^5\|^6`)** | يحتاجان بيانات سيارات حقيقية للمعايرة، وإلا استُبدل خطأ بخطأ |

## ⚠️ ملاحظة على `.env`

`git rm --cached .env` يمنع رفعه مستقبلاً، لكن **المفتاح يبقى في تاريخ Git**.
هذا المفتاح تحديداً من نوع `sb_publishable_` أي عام بالتصميم، فلا خطر منه.
لكن إن أُضيف يوماً `LOVABLE_API_KEY` أو `SERVICE_ROLE_KEY` إلى ملف مرفوع،
